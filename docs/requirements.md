# MyKnownWorld 需求说明

## 1. 项目定位

MyKnownWorld 是一个以个人为中心的认知图谱系统。

它回答：我知道哪些对象存在，我如何认识它们，我拥有、维护或使用哪些对象，它们之间有哪些已知关系，以及变化可能影响哪些与我有关的对象。

系统公开开发，模型和实现保持通用，但首先服务于个人真实信息环境，不以企业 CMDB、多人协作平台或通用文档仓库为目标。

## 2. 核心原则

1. 图谱仅记录我已知的对象和关系，不声称完整描述客观世界。
2. 唯一的 `Self` 是认知锚点；所有已发布节点都与 Self 弱连通，不存在孤岛。
3. 存在、拥有、维护、使用、运行和仅知晓是不同事实，不能互相推导。
4. 明确对象使用明确模型，明确关系使用明确谓词和端点约束。
5. 模糊信息允许阶段性存在，但必须进入可查询、可审查的暂存区，并具有退出机制。
6. 可达不代表信息完整、凭据可得、当前运行或状态正常。
7. 文档正文、秘密值、实时日志、监控流和可再生产物不进入图谱。
8. 当前已有信息是系统的直接建模目标，不是可选的迁移样本；不得要求用户按新模型重新录入世界。

## 3. 当前信息支持范围

以下信息必须能够录入、维护、查询和关联。字段未知不妨碍录入，但不能因此把明确对象降级成万能对象。

### 3.1 我与对象的关系

每个对象需要支持适当的我方关系：

- 我拥有或控制；
- 我承担维护责任；
- 我使用；
- 我仅知晓其存在；
- 我可以受限操作；
- 我曾使用或已停止，但保留历史；
- 我的认识来源、最近确认时间和信息确定性。

`owns`、`maintains`、`knowsAbout` 必须保持独立。使用和受限操作若形成稳定需求，应使用明确关系或模型，不长期塞入备注。

### 3.2 物理硬件

支持记录：

- 名称、型号、设备类别；
- 固定或移动位置；
- 硬件规格；
- 当前状态；
- 直接承载的机器；
- 访问与维护说明引用。

硬件与其 OS 环境必须分开。同一硬件可以承载多台机器，机器迁移应能保留历史。

### 3.3 机器与 OS 环境

支持物理机、虚拟机、共享机器和云实例，并记录：

- hostname；
- OS；
- 一个或多个 IP；
- 所在网络；
- 直接父机器或硬件；
- 现役、模板、退役、销毁等状态；
- 访问方式和访问前提；
- 操作限制、允许范围和禁止事项；
- 共享机器的责任边界；
- 自管目录、端口等资源；
- 当前维护状态和最近核验时间。

不知道 hostname、IP 或其他非关键属性时仍可录入。共享机器仍是明确 Machine，但操作约束必须明确。

### 3.4 软件项目与源码仓库

支持自研、公开上游、纯源码、源码加部署、停滞和弃用项目，并记录：

- 名称、用途、语言和形态；
- 本地路径、远程仓库和上游地址；
- 维护状态；
- 当前推荐版本；
- 继任或替代项目；
- 对应部署实例；
- 相关文档、设计和任务；
- 我拥有、维护或仅知晓的关系。

实例暂时无法关联项目时，允许明确保留未知，不强制创建虚构项目。

### 3.5 软件或服务实例

支持同一产品在多台机器上的多个实例，以及同机同产品的多个实例。记录：

- 实例名称；
- 产品或软件；
- 来源项目，可未知；
- 所在机器；
- 部署路径与部署方式；
- 运行身份或容器身份；
- 域名、URL、IP、端口；
- 配置和部署资产引用；
- 当前生命周期状态；
- 当前与历史运行周期；
- 已确认的其他实例或基础设施依赖；
- 凭据元信息；
- 相关 Runbook 与维护文档；
- 最近验证结果与证据引用。

部署实例不要求当前正在运行。

### 3.6 产品与跨实例共性

确有跨实例共性时支持独立 Product，记录：

- 产品身份与用途；
- 共性配置和操作；
- 共享 Runbook；
- 实例清单及实例差异。

Product 不应成为所有实例强制经过的冗余中间层。

### 3.7 运行历史与状态

区分：

- 已部署但未运行；
- 当前运行；
- 曾经运行；
- 已停止；
- 已迁移；
- 状态未知；
- 某运行周期使用的版本；
- 最近真实验证时间、结果和证据。

部署状态、运行状态和维护状态不能混用一个 status 字段。

### 3.8 凭据与账号元信息

支持：

- 账号标识、用户名或主体；
- 凭据类型、用途和作用范围；
- 所属机器或实例；
- 保管位置引用和获取说明；
- 轮换时间、有效状态和最近核验。

不保存密码、私钥、令牌或可直接使用的完整连接秘密。`hasCredential` 只表示关联和使用，不表示图谱能取得秘密。

### 3.9 网络与访问

支持：

- 域名及其与机器、实例的映射；
- IP、网段、NAT、端口；
- 路由、默认网关、VPN 节点和通道；
- 主备访问路径；
- CA 身份、hosts 映射和客户端前提；
- 在家、外出或其他网络位置下的访问路径；
- 当前与历史访问方式。

网络约定可独立建节点，并与机器、实例和 Runbook 关联。

### 3.10 文档与部署资产

支持一个对象对应多篇不同职责的文档，包括：

- 实例档案、部署说明、配置说明；
- 网络规范、命名规范、工具链说明；
- 架构和决策记录；
- 维护记录、当前风险与观察事项；
- 灾后恢复材料；
- 独立配置资产；
- 索引文档。

文档记录职责、权威位置、描述对象、当前有效性、最近核验和替代/补充关系。正文由原文档系统保存。

### 3.11 Runbook、脚本和恢复材料

支持：

- 适用对象、触发条件和前置访问；
- 步骤、停止条件、回退位置的引用；
- 验证方法、最近验证日期和证据；
- 当前是否可执行；
- 配套脚本、配置和恢复材料；
- 必须人工批准的步骤。

记录 Runbook 不代表获得自动执行权限。

### 3.12 工作、设计和决策

支持提案、设计、待办、冻结、已实施和已放弃事项，并记录：

- 当前与历史状态；
- 决策原因和证据；
- 影响的机器、项目、实例或文档；
- 替代、继任和实施关系。

完成或放弃不等于从认知中删除。

### 3.13 来源、时效和确定性

每条信息应能说明：

- 来源与来源内稳定标识；
- 人工确认、文档声明、现场核验或系统派生；
- 录入和最近确认时间；
- 是否过期、冲突或待审查。

区分文档声明的部署、现场确认的运行、关系推演的影响和仅知晓的对象。

### 3.14 尚未厘清的信息

暂存对象或关系必须记录：

- 原始来源、标题、摘要和元数据；
- 原文引用；
- 候选类型或谓词；
- 待确认问题；
- 审查状态和进入时间。

暂存内容不混入稳定对象统计或默认业务影响分析。

## 4. 稳定节点模型

| 节点 | 定义 |
|---|---|
| Self | 唯一认知锚点 |
| Hardware | 物理设备或硬件载体 |
| Machine | 可启动的 OS 环境 |
| SoftwareProject | 源码项目或软件蓝图 |
| SoftwareInstance | 可识别的部署实例，当前可不运行 |
| RunningPeriod | 实例的一段实际运行时间 |
| AccountCredential | 凭据元信息，不含秘密值 |
| Product | 确有跨实例共性时的产品身份 |
| Document | 稳定知识、规范或部署说明的引用 |
| Runbook | 可重复执行且可验收的流程 |
| WorkItem | 提案、设计、任务、冻结事项 |
| ProvisionalObject | 已知存在但尚未稳定分类的对象 |

公共身份包含稳定 ID、明确类型、名称、来源、生命周期状态、最近确认时间和模型版本。公共身份表不承担万能业务字段。

## 5. 关系模型

业务关系必须有明确含义、方向、端点规则和来源：

| 关系 | 方向与含义 |
|---|---|
| owns | Self → 对象；我拥有或控制 |
| maintains | Self → 对象；我承担维护责任 |
| knowsAbout | Self → 任意节点；仅知道存在 |
| hosts | Hardware/Machine → Machine/SoftwareInstance；承载或部署 |
| implementedFrom | SoftwareInstance → SoftwareProject；实例来自源码蓝图 |
| hasRunningPeriod | SoftwareInstance → RunningPeriod；实际运行历史 |
| hasCredential | Machine/SoftwareInstance → AccountCredential；使用凭据 |
| documents | Document → 对象；文档描述对象 |
| appliesTo | Runbook → 对象；流程适用对象 |
| targets | WorkItem → 对象；工作项影响对象 |
| supersedes | 同类对象 → 同类对象；明确替代 |
| dependsOn | 对象 → 对象；已确认的运行或构建依赖 |

不能从 knowsAbout 推导所有权、维护责任、访问能力、运行状态或业务影响。

未明确的关系进入待审查关系，不伪装成业务关系。

## 6. 连通性、历史与删除

1. 已发布节点必须通过忽略方向的关系路径到达 Self。
2. 新节点最弱的合法接入是 Self — knowsAbout → 节点；获得业务关系后允许保留弱关系。
3. 源文件消失先标记 missing/stale，不自动级联删除。
4. 退役、销毁、停止是生命周期事实，不等于遗忘。
5. 删除必须显式执行，不能无意制造孤岛。
6. 历史运行周期、工作项和映射决策通常保留。
7. 信息不完整不妨碍明确建模，但不能把未知写成已知。

## 7. 分析与推理

所有认知范围、溯源、影响和风险分析从 Self 出发。

- 资产范围沿 owns 和 hosts 查询。
- 维护范围沿 maintains 查询，不能混入仅知晓对象。
- 部署影响沿 hosts、implementedFrom、hasRunningPeriod、hasCredential 和已确认 dependsOn 传播。
- knowsAbout 默认不参与影响传播。
- Document 和 Runbook 提供知识依据，不自动构成运行依赖。
- 分析输出必须展示关系路径，区分事实、派生推断和未知。
- 不从命名、文本链接或相似标题自动推断所有权、维护、部署或凭据可用性。

## 8. 已有信息承接与同步

已有知识库、生命周期材料、源码元数据、旧 CMDB 和人工录入都是一等输入。

每条已有信息必须进入以下之一：

1. 明确稳定对象；
2. 明确稳定关系；
3. 暂存对象或关系；
4. 明确排除并说明原因（正文、秘密值、实时快照、生成物等）。

不得静默跳过，不得为了导入成功随意归入万能类型。

同步必须支持新增、变更、缺失、冲突、预览、重复执行、来源哈希、解析版本和身份映射。重命名不能误认为无关的新旧对象。来源有明确权威范围，不能相互静默覆盖。

导入报告应回答：哪些已明确，哪些缺属性，哪些待分类，哪些因安全边界排除，哪些来源失效或冲突，哪些历史对象仍具价值。

## 9. Web 需求

### 9.1 首页

以 Self 为中心展示我拥有、我维护、我使用、我仅知晓、当前运行实例、待分类对象、失效信息和最近变化。

### 9.2 分类浏览

按明确模型浏览硬件、机器、项目、实例、运行周期、凭据元信息、产品、文档、Runbook、工作项和暂存对象。

### 9.3 对象详情

展示对象定义、我与它的关系、来源、已知与缺失属性、明确关系、运行历史、相关文档和流程、溯源与影响路径、待确认问题。

### 9.4 图探索

支持任意对象设为中心、关系类型/方向/深度筛选、业务关系与 knowsAbout 区分、影响分析默认排除 knowsAbout，并明确派生和待审查关系。

### 9.5 暂存队列

展示未分类对象、待确认关系、长期未复核对象、失效来源和映射建议；通过审查转为明确模型，而不是修改万能字段。

## 10. 接口需求

提供按明确模型查询、查询我与对象的关系、详情与来源、指定关系链、从 Self 的影响分析、运行历史、暂存队列、指定时点图状态和只读同步预览。

MCP 等只读接口应保留认知语义，不以旧 wiki_query 字段结构限制新模型。

## 11. 非目标

当前不做多人权限协作、企业 ITSM/CMDB、实时监控、文档正文仓库、密码管理器、自动执行 Runbook、自动修改生产环境、大模型编造事实，或为兼容旧系统永久双模型双写。

## 12. 公开与私有边界

公开仓库只包含模型、实现、通用同步协议、合成示例和测试。

真实对象数据、来源配置、内部地址、账号、凭据元信息、图谱快照和导入报告保持私有。公开示例不得复制真实个人信息。

## 13. 验收场景

1. 仅知晓的公开项目不出现在我拥有/维护或影响传播中。
2. 项目、机器、实例和运行周期可以独立追溯，停止后历史仍保留。
3. 信息不全的共享机器可明确录入，不推断 owns/maintains。
4. 未分类档案进入暂存区，与 Self 建立 knowsAbout，后续转换保留来源。
5. 停止宿主机能沿 hosts 展示当前受影响对象及路径，不混入 knowsAbout。
6. 所有现有信息都有明确处理结果，重复同步不产生重复对象。
7. 所有已发布节点与 Self 弱连通。
8. 明文秘密、正文和实时快照不进入图谱。

## 最终原则

MyKnownWorld 必须支持我已经积累并需要持续维护的信息。新模型负责逐步澄清已有知识，而不是以完整性门槛拒绝它；准确表达我知道什么、它是什么、它与我有什么关系、我凭什么知道，以及变化与我有什么关系。
