# 实施范围与状态

本计划是可执行的状态清单，不表示产品需求已全部完成。明确需求以 [`requirements.md`](requirements.md) 为准；[`technology.md`](technology.md) 中的技术项是建议，只有在仍符合需求时才采纳。

## 已实现

### 领域与分析

- `internal/graph` 使用封闭节点类型和关系谓词，校验端点、唯一 Self 与弱连通；`owns`、`maintains`、`uses`、`canOperate`、`knowsAbout` 作为 Self 出向关系独立建模；Network 有 `routesThrough` 与 `providesAccessTo`，影响传播纳入 `uses` 和网络访问路径，但排除 `canOperate` 和仅知晓。
- 影响分析按明确方向遍历业务关系，排除 `knowsAbout`、文档和 Runbook，并返回关系路径。
- Hardware、Machine、SoftwareProject、SoftwareInstance、AccountCredential、Product、Document、Runbook、WorkItem、Network 已有互不混用的 Go 类型专属详情和 PostgreSQL 一对一详情表；机器 IP/资源/操作边界、部署端点/引用、凭据元信息（不含秘密）、文档/Runbook引用与工作状态都有合成覆盖。详情字段可缺省，不能因此拒绝对象。
- `RunningPeriod` 已有开始/结束、版本、验证时间/结果和证据引用；验证与时间跨度受到模型校验。
- 字段级 `FieldAssertion` 支持目前已建模字段的来源、证据、确定性、引用和 SHA-256 值摘要；没有保存字段原值。**不得对秘密、文档正文或低熵敏感值做摘要后入库**；它们仍应排除在图谱之外。
- 暂存对象有候选类型、审查问题和 pending/rejected 状态。转换保留对象 ID 与来源元数据，关系端点不兼容时整体拒绝；显式删除 Self 被禁止，删除导致孤岛时拒绝。

### 批量同步与持久化

- PostgreSQL schema v16 有显式迁移、事务化应用、各类对象的一对一详情表、运行周期与字段断言持久化、来源最新状态、成功批次历史和来源身份映射。
- `SourceBatch` 支持预览和原子应用；报告新增/更新/缺失/冲突，并按节点字段暴露跨来源断言分歧（仅断言 ID/来源，不回传值或摘要、不自动裁决）。缺失记录保留并标 stale，不级联删除。相同来源稳定 ID 可幂等更新；显式身份映射解决来源重命名并由 PostgreSQL 后续复用。
- `POST /api/sync/preview` 只读；`cmd/myknownworld-sync` 提供预览及有显式来源确认的 PostgreSQL 应用；`POST /api/sync/apply` 也可通过 bearer token 使用。
- 来源历史接口记录 hash、parser version 和变更 ID，不记录原始输入正文。
- Web UI 已有批次预览/应用面板、受 token 保护的暂存审查/拒绝、来源历史、Self 出向 owns/maintains/uses/canOperate/knowsAbout 分组和影响视图。

### 测试与部署

- `internal/fixtures/synthetic-world.json` 是覆盖全部当前节点类型和关系谓词的合成夹具；Go 单测和 PostgreSQL 隔离 schema 集成测试覆盖导入、重放、连通、审查和存储往返。
- Compose 只在配置强随机 `MYKNOWNWORLD_WRITE_TOKEN` 时启用 HTTP 写入；默认空值禁写，服务默认绑定 localhost。写令牌应保持稳定且不公开。

## 尚未完成的需求切片

1. **模型覆盖深度**：现有类型专属详情是第一版，Network/CIDR/VPN引用与路由、访问关系已有基础模型，仍未逐项覆盖复杂网络拓扑/主备路径历史、产品跨实例差异、资产历史迁移、凭据轮换与范围演变、文档替代链细节、Runbook停止/回退人工审批审计、工作项决策变迁等需求。继续补充时保持明确模型，不能增加万能字段或保存秘密/正文。
2. **可重复导入适配器**：新增通用 Machine inventory CSV 适配器；来源策略支持节点类型/关系谓词/字段精确 allow-list、优先级提示及预览/应用两端范围校验（优先级不自动裁决事实）。尚无真实产品格式适配器、来源插件系统或按 priority 执行的权威裁决（priority 仅提示，不改写真值）。真实来源配置和数据必须留在私有部署。
3. **对象与关系维护**：节点创建（明确 Self 关系、JSON 类型详情）、节点名称/类型详情编辑、关系新增/删除（有连通性保护）已有 API/UI；节点和关系的 Web 手动写入现经统一预览→确认→revision/planHash校验后应用。手动图变更与同步批次都可按指纹条件逆序撤回；批次撤回还恢复来源状态和身份映射，并保留标记已撤回的运行历史。仍缺友好字段表单、关系/字段证据编辑；暂存审查、字段裁决和来源策略编辑尚未接入该统一预览流程。
4. **图探索**：已实现任意对象为中心、方向/深度/谓词筛选、250节点安全上限和截断提示的子图查询；UI使用简单环形 SVG 展示有向关系，并保留 Self 分组与影响视图。仍需改进大图布局、防边重叠，强化事实/推断/待审查图例及历史时点视图。
5. **历史和生命周期**：同步运行历史、字段断言、对象/关系 append-only 变更事件（创建/更新/stale/显式删除）和对象详情时间线已实现；字段分歧可追加裁决（选中一个或多个同字段断言并附安全引用），对象断言查询显示最新裁决且不回传值哈希；不改写证据，也不将其用于未标注的业务查询。真正的业务有效期、整图时点快照/查询和退役/撤销语义仍未实现。事件时间表示系统记录时间，不冒充事实发生时间。
6. **接口与互操作**：当前 HTTP JSON API 尚未完整覆盖要求中的查询/变更协议；只读 MCP 接口和官方 Go SDK 尚未接入。
7. **验收与发行**：目前已对合成数据和本地 PostgreSQL 做验证；还要为新增完整模型、UI工作流和安全行为扩展验收矩阵，并由 CI 完整验证后再发新版。v0.01 是旧发布，不能代表这批未发布改动。

## 研发约束

- 不使用真实个人快照做公开测试；不保存秘密、正文、来源配置或实时监控数据。
- 写入继续要求显式来源、可预览、原子校验和可恢复策略；没有身份验证方案时不能把服务开放公网。
- 完成一项能力必须同步更新模型、数据库迁移、API、UI（若面向用户）、合成夹具、正反例测试和文档；不因本状态文件更新就宣称规划完成。
