# 技术栈与工程约束建议

## 1. 总体要求

技术栈服务于可解释的认知图，不以引入复杂基础设施为目标。首版优先单机、单用户、可备份、可恢复、可测试和可公开运行。

## 2. 后端

- Go 当前稳定版本。
- HTTP 使用标准库 `net/http`。
- 按明确领域模型划分包，避免所有对象都退化为通用 Record。
- 图遍历使用应用层 BFS/DFS 和明确关系规则。
- 不在首版引入图数据库、图扩展、微服务或消息队列。

## 3. 存储

- PostgreSQL 为正式主线。
- SQLite 可用于本地评估和合成示例，但不是默认双写或自动同步目标。
- GORM 可用于明确模型 CRUD 和迁移辅助；复杂图查询使用明确的 Go 查询逻辑。
- 对象身份、明确模型表、明确关系表、暂存对象和来源记录分开。
- 数据模型有显式 schema 版本与迁移，不依赖生产库自动变更。
- 任何凭据秘密和文档正文不进入数据库。

## 4. 前端

- React + TypeScript + Vite。
- 首先实现分类列表、详情、关系路径和简洁关系图。
- 纯 SVG 可满足首版小规模图，不急于引入大型图可视化库。
- 不为兼容旧 CMDB 保留项目/视图/scope 路由或页面结构。
- 前端需明确区分事实、推断、未知、历史与暂存状态。

## 5. 接口

- 领域 API 围绕对象、关系、溯源、影响分析和暂存审查，不以旧 CRUD 为边界。
- 只读 MCP 使用官方 Go SDK。
- API 错误应区分不存在、非法关系、版本冲突、来源冲突和待审查状态。
- 公共 API 不返回秘密、正文或私有来源配置。

## 6. 测试与质量

- 单元测试覆盖模型约束、连通性、影响传播边界和生命周期。
- 集成测试实际覆盖 PostgreSQL；SQLite 示例另行验证。
- 使用合成、公开可分享的图谱作为默认测试夹具。
- 私有真实数据只在私有环境做导入验收，不进入测试或截图。
- 每次行为变更同时更新测试和文档。

## 7. 部署与公开开发

- 首版提供单一后端二进制和可构建前端。
- 默认配置是合成示例，不包含任何私人数据。
- 私有来源通过外部配置或只读适配器接入。
- 项目未初始化 Git、未提交、未发布，仓库治理与许可证后续明确。
- 旧 hall-cmdb 继续运行到新产品具备可替代能力；不做生产双写。
